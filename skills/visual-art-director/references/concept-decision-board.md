# Creative concept decision board — visual comparisons, not AI taste contests

Create a Figma page / section in which A, B and C are comparable at the same desktop viewport and mobile viewport, not isolated cropped posters of unequal quality. Annotate each with:

1. **Concept name + thesis:** what the user should feel or understand, stated in product terms.
2. **UX flow:** what can the visitor actually do, what happens after CTA, and what is the fallback if the effect fails?
3. **Hero's art signature:** lighting, scene, product relationship, type composition, materials, density and negative space.
4. **Distinct interaction:** trigger, effect, real outcome and what the user learns from it.
5. **Visual proof:** real Figma screenshot or source image, mobile plus at least one state.
6. **Hypothesis:** why this direction may help user task and how to test it (preference vote vs first-click / success test vs live experiment).
7. **Costs and risks:** content production, accessibility, performance, implementation, control clarity and maintenance.

Do not simply declare that the most cinematic concept is best. Some users will prefer utility and fast searching. If the brief requires experiments, propose one **conservative usable direction** and two bolder **substantively different directions**, rather than three nearly identical motion-heavy heroes. Do not force this distribution if the product brief implies another.

### Votes

Preference vote asks: 'Which visual direction fits the brand and encourages exploration?' Use side-by-side screenshots and record participant segment, sample size, question, count and uncertainty. A usability task asks: 'Find the delivery terms / select a category / discover an offer' and records completion, hesitation and errors. Neither proves a future conversion lift.

### Rejection

Reject a direction if its visual difference from another is merely color/type, it could represent any brand with a logo swap, its signature effect obscures task completion, mobile makes the key action unavailable, or it relies on assets that cannot be sourced/licensed. Revision must change layout/media hierarchy or interaction concept, not sprinkle decorative effects.

### User-guided selection checkpoint

When the user wants to collaborate, the designer asks one focused comparison question after showing actual A/B/C visual proofs and a recommendation: pick an option, combine strengths, or offer a correction. Record the actual answer in the Decision Ledger. A preference is `selected`, not `approved`; implementation still requires explicit authorization. When the user already chose, do not reopen the same decision without cause.
