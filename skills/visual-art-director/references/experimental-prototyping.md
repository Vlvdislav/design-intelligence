# Experimental-first — only on explicit request after Figma concept selection

## Когда включать

Не включать автоматически. По умолчанию этот skill делает Figma-first концепции и motion storyboards БЕЗ frontend и без временного HTML. Разрешай локальное исследование движения только если пользователь прямо просит runnable proof или отдельно соглашается на такую исследовательскую проверку после выбора направления.

Ни подробный MotionSites prompt, ни сложная пространственная сцена сами по себе **не дают** разрешения создавать код. Эксперимент с кодом не является конечным deliverable и никогда не заменяет Figma.


## Разрешённый объём

- 1 маленький локальный HTML-файл, CSS и vanilla JS как **temporary canvas**;
  Playwright/скриншот через доступный реальный инструмент.
- Допустимы изображения-ассеты (пользовательские или с разрешённым источником).
- Никаких внутренних сервисов, API-ключей, базы данных, формы оплаты,
  пользовательских аккаунтов, деплоя/хостинга, npm-проекта ради простого теста.
- Если проект пользователя уже открыт, прототип храни отдельно (temp/artifacts),
  не перезаписывай его файлы и не коммить без явного запроса.

## Алгоритм

1. Из Scene Blueprint выдели минимальный набор для теста:
   **фон + hero + 3–5 репрезентативных карточек + nav + выбранное состояние**.
2. Построй geometry: anchors, scale, perspective, z-order, opacity, blur.
   Не генерируй всё под единое background image.
3. Добавь только ключевые interaction states: click/drag/keyboard и
   transition. Статический Figma-экспорт тоже должен отражать все состояния.
4. Открой прототип локально доступным браузером и сделай screenshots:
   desktop idle, desktop midpoint, desktop settled, mobile idle и mobile
   selected. Не утверждай, что проверил экран, если не смог его увидеть.
5. Проверь изображение и визуальные проблемы: clipping, оптический баланс,
   контраст на реальном фоне, пересечение CTA, размер карточек, mobile.
6. Исправь реальную проблему в CSS/геометрии; перерендери ключевой кадр.
7. **Перенеси в Figma:** если доступен `generate_figma_design`, захвати
   локальную страницу/несколько состояний. Если работает `html_to_figma`,
   можно передать HTML для статичных слоёв без сервера. Используй именно
   фактически описанные аргументы текущего Figma MCP; не выдумывай схему.
8. После захвата выдели семантические части: `Hero stage`, `Product card`,
   `Buy bar`, `Navigation`, `Overlay`. При наличии `use_figma` переоформи
   повторяющиеся интерфейсные части native component/instances, bind tokens
   и auto layout. Spatial stage остаётся свободно позиционируемым фреймом.
9. Создай как минимум 5–7 **state frames**, чтобы Figma отражала UX-механику.
   Добавь краткие motion annotations (trigger, duration, easing, reduced).
10. Выполни Figma screenshot QA; сравни по визуальным опорным точкам с
    браузерными снимками. Документируй различия и исправленные элементы.

## Что нельзя обещать от захвата

- `generate_figma_design`: захватывает рендеренный UI как **flat editable
  layers**, не переносит JS-логику и не восстанавливает автоматически
  компоненты дизайн-системы. Внешние CSS-фильтры могут передаваться не 1:1.
- `html_to_figma`: переносит HTML в дизайн-слои, а не интерактивный JS runtime;
  некоторые динамические эффекты требуют статичных сохранённых состояний.
- `send_code_to_figma`: отправляет **кодовый слой / Figma Make**,
  **не** редактируемые Figma design layers. Не подменяй им задачу.
- `use_figma`: native layers и компоненты, но Figma не запускает произвольную
  браузерную физику. Прототипировать анимацию штатными средствами можно
  только если они доступны и действительно выполнены.

## Протокол сравнения снимков

Для каждого кадра сравни:

| Условие | В браузере | В Figma | Что делать |
|---|---|---|---|
| Anchor hero | X/Y и масштаб | тот же визуальный центр | правка позиции |
| Карточки | размеры, угол, скрытие | сохранение глубины | восстановить порядок слоёв |
| Текст | реальный copy, вес, перенос | редактируемые text nodes | исправить font/spacing |
| Glass | blur, контраст, границы | визуально приемлемая альтернатива | ручное уточнение |
| CTA | виден и не перекрыт | читаемый/кликабельный | выдвинуть слой/контраст |
| Mobile | 390px, touch UX | mobile frame | адаптировать, не уменьшать |

Если доступно, используй автоматическую разницу снимков как вспомогательную
проверку, но не принимай слепо метрики сходства: текстовый рендеринг,
цветовые профили и снимки анимаций могут отличаться.

## Работа с отсутствующими инструментами

- Browser/screenshots недоступны → не выдавай черновой код за проверенный;
  по возможности переходи в Figma-native и проверяй скриншоты там.
- Figma capture недоступен → native authoring через `use_figma` и storyboard.
- Нет Figma-write → можно отдать изображения/спеку, **но не заявляй, что
  Figma создана**.
- Пользователь хочет только Figma → не передавай ему исходники temp-прототипа
  без просьбы; это внутренний инструмент, а не итог.
