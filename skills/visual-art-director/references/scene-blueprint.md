# Scene Blueprint — от художественной идеи к исполнимой спецификации

## Цель

Пользователь описывает **замысел**, агент сам выводит **визуальную механику** и
измеряемые параметры, затем уточняет их по реальному рендеру. Не требуй от
пользователя знания CSS, 3D, easing и Figma API.

## 1. Уровни знания и точность

Каждую существенную деталь маркируй в рабочих заметках:

- `[GIVEN]` — буквальная цифра/название/ограничение пользователя, не изменяй;
- `[OBSERVED]` — увидено в проверяемом референсе (URL/скриншот, что именно);
- `[DESIGNED]` — твой авторский параметр, подлежащий визуальной проверке;
- `[UNVERIFIED]` — нужна проверка ассета/шрифта/инструмента.

Не придумывай «точные» тайминги, размеры, URL как будто они извлечены из
референса. Для нового дизайна значения допустимо изобретать как рабочие гипотезы;
их статус — DESIGNED, а не GIVEN. Если пользователь просит exact recreation,
списывай его данные дословно.

## 2. Scene Blueprint — минимальный рабочий шаблон

```yaml
scene:
  goal: "..."                  # сценарий и желаемое ощущение
  canvas:                      # DESIGNED если не задано
    desktop: [1440, 900]
    mobile: [390, 844]
    safe_areas: "..."
  hierarchy:                   # 1 герой, 2 вторичных, 1 CTA
    hero: "..."
    secondary: ["...", "..."]
    action: "..."
  layers:                      # с явным z-order
    - {name: "room", depth: -2, content: "..."}
    - {name: "brand-word", depth: -1, content: "..."}
    - {name: "product-orbit", depth: 0, content: "..."}
    - {name: "subject", depth: 1, content: "..."}
    - {name: "controls", depth: 2, content: "..."}
  art_direction:
    lighting: "..."
    material: "..."
    image_treatment: "..."
    spatial_logic: "..."
    typography: "display / UI / price / utility"
  assets:
    - {role: "subject", source: "verified URL/local file or needs-generation", status: "UNVERIFIED"}
  interaction:
    input: ["pointer", "touch", "keyboard"]
    states: ["idle", "hover", "select", "transition", "settled"]
    focus: "..."
    fallback: "..."
  motion:
    signature: "..."
    trigger: "..."
    duration_ms: "DESIGNED after prototype"
    easing: "..."
    reduced_motion: "instant swap"
  responsive:
    mobile_reflow: "..."
    touch_hit_areas: "..."
  figma_mapping:
    native: ["text", "buttons", "tabs", "buy-card"]
    image_assets: ["background photo", "product photo"]
    scene_states: ["idle", "selected", "transition middle", "mobile"]
    non_transferable: ["continuous JS physics"]
```

Не показывай этот YAML пользователю как единственный результат. Он внутренний
план действий и источник параметров для рендера/макета.

## 3. Как выбрать узнаваемую визуальную механику

Не «поставь карточки в 3D». Выдели физическую метафору:

| Метафора | Визуальный закон | Зачем в интерфейсе |
|---|---|---|
| Орбита / галерея | объекты уменьшаются и поворачиваются с удалением | исследовать коллекцию |
| Световая скан-линия | reveal-маска следует за линией | смена состояния/варианта |
| Магнитные объекты | блоки мягко притягиваются к фокусу | выделение активного товара |
| Слоистое стекло | локальный blur зависит от глубины | панель управления поверх сцены |
| Редакционная панорама | диспропорции фото и типографики | раскрыть историю коллекции |
| Интерактивный стол | пространственные группировки по назначению | собрать комплект |

Смешивай 1 основную механику и максимум 1–2 поддерживающих; не вставляй все
эффекты сразу. Разрабатывай свои метафоры, не копируй шаблон VirtualFit.

## 4. Из идеи в значения

Для каждого ключевого элемента определи:

1. **Anchors:** относительно какого края/центра расположен блок.
2. **Dimensions:** размер зависит от viewport, компонента или текста.
3. **Depth:** масштаб, blur, поворот, opacity, порядок перекрытия.
4. **Behavior:** вход, hover, drag, выбранное, уход, responsive.
5. **Test:** каким скриншотом/кадром докажешь, что элемент работает визуально.

Пример авторской формулы для карусели (не универсальная и не «из источника»):

```js
const distance = Math.abs(index - position);
const scale = 1 / (1 + 0.26 * Math.pow(distance, 1.12));
const rotateY = Math.sign(index-position) * Math.min(34, 13 * distance);
const blur = Math.max(0, distance - 1.5) * 2.2;
```

Прогони визуально хотя бы 0, ±1, ±2 и mobile; отрегулируй значения, если
центр перекрывает CTA или дальние карточки превращаются в мусор.

## 5. Asset map

- Любой внешний URL должен реально существовать и загружаться; не создавай ссылки
  на основе угадывания названий файлов.
- Генерируй отдельные ассеты: фон, модель/объект, карточные изображения; не
  генерируй весь интерфейс как один плакат для финальной Figma.
- Для персонажа в последовательности состояний важны идентичность, перспектива,
  пропорции, освещение и постоянный ракурс; иначе scan-reveal выдаст скачок.
- Crop/sprite-сетки при необходимости должны иметь проверенные размеры; если
  их нет, лучше отдельные согласованные изображения.
- На правах коммерческого проекта сохраняй ограничения лицензии и чужие бренды.

## 6. Проверка исходного и конечного состояния

Перед сдачей сравни 3 столбца: `Brief requirement / Visible evidence / Figma node
or frame`. У отсутствующей механики должен быть честный статус `not implemented`.

Если screen state существует только в JS, сохрани: статичный кадр состояния,
описание триггера, длительность/easing и ссылку на локальный прототип (если
пользователь просил получить его как отдельный файл); **не называй статичный
кадр работающей анимацией в Figma**.
